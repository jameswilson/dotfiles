# Work context

## Developer workflows

- Prefer practical, technically detailed guidance over high-level summaries when depth is requested.
- Investigate how tools work internally when diagnosing compatibility or integration problems.
- Preserve Git history when moving projects between systems.
- Use concise, technically precise writing for documentation, Slack, Jira, and engineering recommendations.
- Follow technical changes that affect active projects and engineering productivity.

## Developer briefings

- Daily developer briefings prioritize:
  - Drupal and web development.
  - AI and developer tooling.
  - Open-source software.
  - Deep technical updates, releases, security news, and breaking changes.
  - Relevant developments in the United States, Ecuador, and Latin America.
- Weekly Drupal briefings prioritize:
  - Drupal 10 and Drupal 11.
  - DDEV, Drush, and Composer.
  - Contributed modules and security advisories.
  - Deprecations, compatibility changes, tooling updates, and migration implications.
  - Actionable consequences for active sites.

## Automation and integrations

- Morning workflows combine calendar events, unread email, Slack activity, Jira updates, and recent standup notes from Google Drive.
- Briefings should be concise and decision-ready.
- Slack-delivered briefings should retain useful reference links.
- Scheduled prompts, cloud execution, and integrations should fit existing workflows rather than create parallel systems.
